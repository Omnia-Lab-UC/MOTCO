    Corrected-permutation check — 2026-10-30

    This report validates the residual-corrected RRPP null that MOTCO 0.13.0 offers as the opt-in residual_correction (openspec change residual-df-corrected-permutation, spec corrected-permutation-validation). It is the follow-up that the case-study configuration diagnosis named with its residual_df_shrinkage verdict, and roadmap item 8.

    1. Construction

    scripts/corrected_permutation_check.py (design D5–D7) builds every unit with the parent check's code (case_study_type_i_check.build_unit) and settings, with four overrides: base seed 2031, the named cohort table, the profile's δ, and the profile's cells.

    Fixed across runs (each run's settings.json): - the Phase 6 replicate: three stages, methylation + expression, joint magnitude and p_dmp 0.1; - the confounded covariate z = 0.5·g + 1·s + 2·g·s + ε, injected at s_z = 10 into a fifth of the features along a fixed direction; - five i.i.d. N(0, 1) noise covariates x1–x5, so the trajectory model declares six covariate columns and p_red = 10; - the rank floor of 2, net displacement, the harness CV knobs, 500 replicates and 999 permutations.

    Fresh family (design D7). Base seed 2031 is used by no committed check. Every seed derives from it and the replicate index, including the injection direction, the covariates, the generator and RRPP. The diagnosis chose the remedy on the parent's base seed 2026, so a test on those replicates would have been circular.

    3. The uncorrected null

    uncorrected_excess_reproduced: false. The flag asks whether the uncorrected pooled delta exceeds 0.0597 in either table. It reads 0.046 (astrocyte) and 0.045 (microglia). On the parent's family the same model read 0.066 pooled (z_noise5 in the diagnosis, §2).

    As predeclared (design, Risks), the correction's size verdict stands either way, and no rule was re-tuned. The evidence that column count drives the delta excess remains the diagnosis's within-family contrast C2 (p = 0.015). This check runs every arm at the same six covariates, so it has no column contrast and cannot re-test that mechanism.

    The uncorrected null is still liberal at this configuration, on other statistics. The descriptive uncorrected block lists three failing entries: - pooled shape 0.0685 (astrocyte) and 0.0675 (microglia) against 0.0597. They also fail the clustered sensitivity. The parent family read 0.0615 for the same model (diagnosis, §2). - power anchor angle, 43 / 500 = 0.086 against 39 / 500, at the Phase 6 stage effect.

    Every corrected arm holds all three: df reads shape 0.058 and 0.052 pooled and power anchor angle 32 / 500. So the narrowed Freedman–Lane null shows up on different statistics in different seed families and designs: - delta on the parent family; - shape on this family's Type I runs; - angle at this family's strong-signal anchor.

    The correction removes the excess in each case, because it widens the null for every statistic at once.

    For sead_sexdiff. - The covariate-adjusted primary, withheld since the case-study Type I check, is re-issued for both cell types with --residual-correction df under MOTCO 0.13.0, in its own change. - Under df its delta, angle and shape p-values are size-controlled at this configuration: pooled 0.029–0.058 per table and statistic, at most 32 / 500 per reading. - delta is conservative under df here (0.029 and 0.031 pooled). A delta non-rejection therefore stays weak evidence, as before. - The earlier caveats stand: the angle null is too wide to inform a non-rejection, and the CV-selected rank is reported beside any angle result. - The stage latent-adjusted arm is not touched by this check and stays inadmissible at this configuration (diagnosis, residualized_basis).

    For MOTCO. - residual_correction="df" (--residual-correction df) is documented as validated at the case study's configuration. It stays opt-in, and without it every output equals 0.12.0's. - leverage holds size too, and it is kept. It is not the validated choice, because it earned no paired advantage. - Whether df should become the analysis default is a separate, later change. A default flip changes every covariate-adjusted output and needs its own fixture re-issue (tasks, "Workflow follow-up").

    7. Limitations and scope

    • cohort_50 tables not run. The case study's sensitivity tables, for example microglia cohort_50 at n = 63 with κ = 1.090, were not run. The shrinkage grows with p_red / n, so the uncorrected null is expected to be more liberal there and the correction to matter more. The correction's size there is inferred, not measured.
    • Additive-linear covariates. z enters the features additively along one fixed direction, and the trajectory model linearly. The five noise covariates are i.i.d. normals, unlike the case study's age, education, PMI, RIN and library sizes. The correction depends on n and the reduced rank only, but its size at the real covariates is inferred.
    • Structural-analogue blocks. The blocks are InterSIM-calibrated methylation and expression analogues (498 measured features), not the case study's TMM log2-CPM blocks of 5,000 features each.
    • Calibration on the astrocyte table only. δ and s_z were calibrated on the astrocyte table by the parent check and not re-tuned. The microglia runs read inside the band (§1), so this did not bite, but it was not designed for.
    • Power on one table and one strength. The power run uses the astrocyte table at δ = 2.0, where the statistics have power. The weak-signal runs hold only null controls, so the cost at the case study's stage signal is not measured.
    • The delta excess was not replicated. The mechanism rests on the diagnosis's C2 (§3). The uncorrected arm's pooled delta on this family is at α, which means that df is conservative for delta here.
    • What stays on ing. records/ (4.0 MB per Type I run, 26 MB for power) and the power run's 63,000-row corrected_permutation_pvalues.csv (2.6 MB) stay there, under /home1/tgonza/MOTCO/results/corrected-permutation-2026-10-30/ with the SLURM logs. They were moved there from the run's worktree on 2026-10-31, and their digests were rechecked.
