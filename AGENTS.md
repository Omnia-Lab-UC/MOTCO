# Repository Guidelines

This is the single source of truth for coding agents and contributors working in this repository. `CLAUDE.md` imports this file; edit here, not there.

## Project Structure & Module Organization

MOTCO is a Python package using the `src/` layout. Core package code lives in `src/motco/`; the CLI entry point is `src/motco/cli.py`, and statistical routines are split under `src/motco/stats/` (`pls.py`, `snf.py`, `design.py`, `trajectory.py`, `permutation.py`). The simulation framework is under `src/motco/simulations/`. Tests live in `tests/`, with fixtures and reference CSV/R data under `tests/data/`. Documentation is in `docs/` and is built with MkDocs using `mkdocs.yml`. Example usage is in `examples/motco_example.ipynb`. OpenSpec proposals and canonical specs are under `openspec/`. See [Architecture](#architecture) for module-level detail.

## Build, Test, and Development Commands

Use Python 3.11+ and `uv`.

```bash
# Install (lockfile-respecting, matches CI)
uv venv && source .venv/bin/activate
uv sync --extra test   # add --extra docs for MkDocs; or: uv pip install -e ".[test]"

# Lint
uv run ruff check src/ tests/

# Type check
uv run mypy src/motco/

# Run fast tests
MOTCO_TEST_PERMS=99 uv run pytest tests/ -m "not slow" --tb=short

# Run a single test file
uv run pytest tests/test_trajectory.py -v

# Run slow regression tests with parallelism (only on main in CI)
MOTCO_TEST_PERMS=10000 MOTCO_N_JOBS=-1 uv run pytest tests/ --tb=short

# Pre-commit gate — all three must pass before committing
uv run ruff check src/ tests/ && uv run mypy src/motco/ && MOTCO_TEST_PERMS=99 uv run pytest tests/ -m "not slow" --tb=short

# Docs preview
uv run mkdocs serve

# CLI entry point
motco --help
motco plsr --help
motco snf --help
motco simulate --help   # numpy generator (no R at runtime)
motco de --help
motco analyze --help    # real-data entry point (motco.analysis)
```

## Coding Style & Naming Conventions

Target Python 3.11. Keep line length at 120 characters, matching `pyproject.toml`. Ruff enforces `E`, `F`, `W`, and import-order (`I`) rules. Prefer explicit, descriptive function and variable names for statistical code; keep public APIs stable and documented with docstrings. Test files should follow `test_*.py` or `*_test.py`.

## Testing Guidelines

Tests use `pytest` with configuration in `pyproject.toml`. Slow tests are marked `slow`; use `MOTCO_TEST_PERMS=99` for fast permutation tests during development and the full regression command above before merging numerically sensitive changes. Add tests alongside behavior changes, especially for numerical fallbacks, CLI validation, and reference-data comparisons.

## Commit & Pull Request Guidelines

Follow the existing Conventional Commit style: `feat:`, `fix:`, `docs:`, `chore:`, and `refactor:`. Keep commits focused and imperative, for example `fix: handle singular model matrix fallback`. Pull requests should include a short problem statement, summary of changes, commands run, linked issues or OpenSpec changes when relevant, and screenshots only for documentation or rendered output changes.

## Agent-Specific Instructions

When running shell commands as an agent, prefix commands with `rtk` if it is installed (`command -v rtk`); otherwise run them directly. Do not overwrite user changes; inspect the worktree before broad edits and keep changes scoped to the requested task. When a change alters architecture, defaults or conventions described below, update this file in the same change.

## Architecture

MOTCO is a Python package (`src/motco/`) with a CLI entry point (`motco`) and statistical modules under `src/motco/stats/`:

- **`stats/pls.py`** — PLS-DA with double cross-validation (`plsda_doubleCV`). The outer loop (CV2) picks the best model per repeat; the inner loop (CV1) selects the number of latent variables by AUROC. Returns a dict with `"table"` (DataFrame) and `"models"` (list of fitted `PLSRegression`). Optional parallelism via `n_jobs`. Keyword-only `scale` (every PLS fit), `nuisance` (a `NuisanceDesign`: every training set estimates its own covariate coefficients on `[1, conditioning, covariates]` via `fit_nuisance_coefficients` and residualizes its held-out rows with them via `residualize`; result gains `nuisance_min_training_df`) and `strata` (fold stratification labels instead of `y`; same-partition labels give the default folds); the defaults are byte-identical (`tests/data/plsda_doublecv_identity.json`). Keyword-only `min_components` (default 1) floors the CV candidates at `min_components … max_components − 1` (`1 ≤ min_components < max_components`, else a `ValueError` naming both before any fit; the outer-fold selection is by candidate value), so every table `LV` and refit model is at or above it; `motco plsr --min-components` exposes it with the primitive's default, so the generic tool's output is unchanged — the floor of 2 is the trajectory measurement's rule (`fit_pls_latent_space`), not the primitive's. Keyword-only `sparsity` (a `SparsityDesign`, 0.22.0) makes every fit a `SparsePLSDA` and scores every (rank, keep fraction) pair in the inner loop, ordered rank ascending then fraction descending so the first-occurrence `argmax` ties to the smaller rank, then the fuller budget; each repeat takes the modal rank (smaller on ties) and the modal fraction (fuller on ties, `_modal_fraction_fullest`), the table gains `keep_fraction` after `LV`, and the refits are sparse; groups not covering `X` are a `ValueError` before any fit, a `[1.0]` ladder reproduces the run without it exactly, and absent the output is byte-identical (no column). `fit_plsda_model(..., sparsity=, keep_fraction=)` fits the same estimator. `calculate_vips(model)` computes VIP scores from a fitted model.

- **`stats/sparse_pls.py`** — Sparse PLS-DA (0.22.0). `SparsePLSDA(n_components, keep, *, groups=None, scale=True, max_iter=1000, tol=1e-6)` subclasses `PLSRegression` and overrides only `fit`: at the full budget it calls `PLSRegression.fit` (bit for bit), below it it mirrors sklearn's `_PLS.fit` (regression mode, NIPALS; sklearn's `validate_data`, `_center_scale_xy`, `_svd_flip_1d`, `pinv`) with the power method's X weight soft-thresholded per group before normalization (`soft_threshold`: keep the `keep` largest absolute entries, shrink them by the largest discarded one, zero the rest; ties to column order). It inherits `transform`, `inverse_transform`, `predict`, `x_rotations_`, `x_scores_`, `_x_mean`/`_x_std`, so every consumer of a PLS-DA model accepts it, and adds `keep_` (count per component × group), `support_` (non-zero weights, features × components) and `support_sizes(groups)`; `keep`/`groups` are validated in `fit` before any component, naming the value. sklearn's NIPALS stops at a squared weight change below `tol`, ~2e-3 from the exact singular vector, which is why the estimator reuses sklearn's iteration rather than its own. `SparsityDesign(scope, keep_fractions=DEFAULT_KEEP_FRACTIONS, feature_groups=None)` (`SPARSITY_SCOPES` = `joint` | `block`; ladder 1.0/0.5/0.2/0.1/0.05, distinct in (0, 1], held fullest first; block needs groups; `resolve(n_features)`, `counts(f)` = `max(1, round(f·p_g))` halves up, `estimator(rank, f, scale=)`, `to_dict()`). Reference: `tests/data/splsda_reference_fixture.npz`, made once by `tests/data/reference/splsda_fixture.R` (mixOmics 6.34.0 `splsda`, `scale = FALSE`, `tol = 1e-20`; flake `rPackages.mixOmics`) and packed by `tests/splsda_fixture_capture.py`: identical supports, weights 3e-11 and scores 1e-10 apart at `tol=1e-24`. Tests: `tests/test_sparse_pls.py`, `tests/test_plsda_sparsity.py`.

- **`stats/snf.py`** — Similarity Network Fusion. `get_affinity_matrix` → `SNF` → optional `get_spectral(n_components=10)`. Input datasets must be sample-aligned (same rows, same order).

- **`cli.py`** — Argparse CLI with five subcommands: `plsr`, `snf`, `simulate` (semi-synthetic multi-omic dataset via the numpy generator, no R), `de` (`--orientation-estimator {pc1,net_displacement}`, default `pc1`; the JSON gains an `orientation_estimator` key only when the flag is given, so default output is byte-identical), `analyze` (over `motco.analysis`; `--min-components`, default 2, the latent rank floor; `--residual-correction {df,leverage}`, default absent; `--span-split-test`, default off, one printed line with the three pseudo-F p-values and the in-span share, a clean error with `--latent-adjustment`; `--interaction-scan`, default off, one printed line with the maximum F and its feature, the global p-value and the hits at adjusted p ≤ 0.05, and `interaction_scan.csv`; `--block-weighting {equal_variance,mfa}`, default absent, the kind printed beside the rank floor; `--sparsity {joint,block}` and `--sparsity-ladder F1,F2,...` (0.22.0, default absent; the ladder without `--sparsity` or not fractions exits non-zero), the scope and selected keep fraction printed beside the rank floor). `plsr` takes `--min-components` (default 1, the primitive's unfloored rule). Each wraps the corresponding module and converts `ValueError` to clean `SystemExit` messages.

- **`analysis.py`** — The **real-data entry point** (`analyze_trajectories(TrajectoryDataset, TrajectoryAnalysisParams)` → `TrajectoryAnalysisResult`; `write_analysis_outputs`; CLI `motco analyze`). Inputs: named `OmicsBlock`s (any names/count, declared unit transform `identity` | `beta_to_mvalue`, concatenated in declared order as `block__feature`), metadata with caller-named sample/group/stage columns, exactly two groups, and an **explicit `stage_order`** (load-bearing for net displacement; never sorted) — honoured by recoding group/stage to ordinal strings before `build_simulation_trajectory_design` and mapping levels back. It calls the **same cores** as the harness (`preprocessing.fit_block_scalers`/`transform_blocks`/`concatenate_blocks(order=)`, `evaluation.fit_pls_latent_space`, the record helpers), so `tests/test_analysis.py::test_matches_harness_*` requires identical latent matrices, statistics, p-values, rank, null summary and spectrum. Defaults: `orientation_estimator="net_displacement"`, harness CV knobs, `forced_components` for dimensionality sensitivity, and the **rank floor** `min_components=2` (0.10.0; `1` restores the unfloored 0.9.0 rule, normalizes to `None` and is dropped from `to_dict()` and from the record's `latent.integration_params`, so the identity fixtures run with `min_components=1`; a floor below 1 is rejected before fitting; `resolved_min_components` is passed to the core; CLI `--min-components`, printed beside the selected rank). The floor guarantees two dimensions, not a second axis with signal: `config_spectrum`'s eigengap and the null summary say how resolvable orientation is. The record carries statistics, p-values, `null_summary`, `config_spectrum`, latent metadata (selected rank, component selection), design (ordered levels, cell sizes), block units, params and software versions — no `truth_metadata`/`realized_geometry`. The trajectory pipeline (group differences) is split across three modules — `design` → `trajectory` → `permutation`:

- **`stats/design.py`** — Design construction.
  1. `get_model_matrix(X, group_col, level_col, full)` — builds an intercept + dummy-coded design matrix with optional group×level interactions. Category order is deterministic (sorted string representation).
  2. `build_ls_means(group_levels, level_levels, full)` — generates the LS-mean row vectors consistent with the coding from `get_model_matrix`. Row order is group-major, level-minor.
  - `center_matrix(...)` — column-centering helper used by the estimators.

- **`stats/trajectory.py`** — Estimation + geometric metrics.
  - `estimate_difference(Y, model_matrix, LS_means, contrast)` — fits betas via normal equations (Cholesky → direct solve → lstsq fallback), then computes per-group trajectory size (`_estimate_size`), orientation (`_estimate_orientation` via eigendecomposition), and shape (`_estimate_shape` via strict pairwise ordinary Procrustes alignment over all orthogonal transforms — reflections aligned away at every ambient dimension). Returns symmetric matrices `(deltas, angles, shapes)`. `estimate_betas`, `get_observed_vectors`, and `pair_difference` expose the beta/LS-mean prediction step directly.
  - **Net-displacement estimator (opt-in at the primitives, harness default).** `estimate_difference(..., orientation_estimator="net_displacement")` (also on `RRPP` / `_RRPPWorker` and `diagnostics.geometry_from_means`) measures each group's orientation as the unit vector `stage_last − stage_first`; it equals PC1 at two stages, stays defined on near-isotropic configurations, and gives `NaN` (reported unavailable) on a zero displacement. Only `angle` depends on it; the primitives' default `"pc1"` is byte-identical. The simulation harness defaults to net displacement, so real-data code calling the primitives directly must pass `orientation_estimator="net_displacement"` to measure what the harness measures.
  - **Orientation sign convention deviates deliberately from the reference supplement.** PC1 is signed by net displacement `PC1 · (stage_last − stage_first)`, not by the supplement's raw first-stage row (`evo_649_sm_suppmat.r:64`), which would make the sign depend on the trajectory's position relative to the coordinate origin. See the `_estimate_orientation` docstring and `tests/test_trajectory_orientation.py` for the invariance contract.

- **`stats/permutation.py`** — `RRPP(Y, model_full, model_reduced, LS_means, contrast, permutations, n_jobs)` — permutes residuals of the reduced model and calls `estimate_difference` for each permutation. Serial by default; parallel via `multiprocessing.Pool` using `_RRPPWorker` (a picklable callable). Opt-in `residual_correction` (`RESIDUAL_CORRECTIONS = ("df", "leverage")`, 0.13.0) rescales the reduced residuals once before either path — `df` by κ = √(n / (n − r)), `leverage` by 1/√(1 − h_ii), r the reduced model's numerical rank — leaving the permutation indices, the fitted values and the full-model estimation unchanged; `residual_correction_scale(model_reduced, correction)` returns the multipliers and raises for an unknown value, n − r ≤ 0 or a leverage-1 row, before any draw. `None` (default) is the untouched path, byte-identical to 0.12.0.

- **`stats/interaction.py`** — `interaction_split_test(Y, model_full, model_reduced, basis, *, permutations, seed, residual_correction, return_null)` (0.18.0) tests the group × stage interaction in three parts: `total`, `span` (`Y·Q·Qᵀ`, `Q` orthonormal to 1e-8) and `complement` (`Y·(I − Q·Qᵀ)`, non-empty). Per part (`InteractionSplitPart`): dimension, interaction SS ‖(H_F − H_R)·Y_part‖², the full model's RSS, df_int = rank(F) − rank(R), df_res = n − rank(F) and the trace pseudo-F; `span` + `complement` = `total` exactly for both sums, and `InteractionSplitResult.span_share` is the span's share of the interaction SS (`None` at zero). Permutation is Freedman–Lane with `RRPP`'s serial draws (`default_rng(seed)`, one `permutation(n)` per draw) and its residual corrections (`residual_correction_scale`, rows scaled before any draw; under `df` the F null is unchanged and the SS null scales by κ²), on each part's `n × n` reduced-residual Gram matrix (formed once from `E·Q` and `E − (E·Q)·Qᵀ`), so a draw costs O(n²) whatever p. p-values are (1 + #{null ≥ obs}) / (1 + B) for the pseudo-F (the statistic: its ratio cancels the residual shrinkage) and the interaction SS (a diagnostic). Inputs are validated before any draw (rows/columns, finite, orthonormal basis naming the largest deviation, nested models, positive df). Imports nothing from `motco.simulations`; the caller maps features to the basis's coordinates. Tests: `tests/test_interaction_split.py`. `interaction_feature_scan(Y, model_full, model_reduced, *, permutations, seed, residual_correction, return_null)` (0.20.0) tests the same interaction one column at a time: per feature SS_int, RSS and F = (SS_int/df_int)/(RSS/df_res) (affine-invariant; the sums add to the split test's `total`); a column whose RSS ≤ 1e-12 of its centred SS, or constant, is degenerate (no F, no p-value, out of every maximum; all degenerate raises before any draw). `InteractionScanResult` holds the per-feature arrays, `max_f`/`max_column` and, with permutations, `p_value_global` (the maximum F's permutation p-value), Westfall–Young step-down max-T `p_value_adjusted` (order by F descending, ties by column index; suffix maxima per draw; running maximum; the top one is the global p), `null_max_f` / `null_max_column` per draw, the draws × columns `null_f` only with `return_null`, and `hits(alpha=0.05)` (`INTERACTION_SCAN_ALPHA`). Draws are RRPP's serial sequence on the reduced residuals with its corrections (a constant multiplier — `df` — is not applied, since it cancels in every F, so every null F and p-value is identical); each draw is one `W[argsort(π)]ᵀ·E` product (O(n · rank(F) · p)), no permuted n × p matrix. Both functions share the validation and column-space helpers (`_model_spaces`). Tests: `tests/test_interaction_scan.py`.

### Key conventions

- All model matrices must include an intercept column. `get_model_matrix` always prepends one.
- `contrast` is a `list[list[int]]`: each inner list enumerates the LS-mean row indices belonging to one group (group-major, level-minor indexing matches `build_ls_means`).
- `group_col` and `level_col` must always be passed explicitly — no defaults anywhere.
- `MOTCO_TEST_PERMS` controls permutation count in regression tests (default `10000`). `MOTCO_N_JOBS` controls RRPP parallelism (default `1`; use `-1` for all CPUs).
- Regression test reference values are in `tests/data/results_example1.csv` and `tests/data/results_example2.csv`. `tests/data/reference/` contains the R script used to generate them, not CSV outputs.
- The package is built with `hatchling`; version is sourced from `src/motco/__init__.py`.
