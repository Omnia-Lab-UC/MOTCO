# Repository Guidelines

This is the single source of truth for coding agents and contributors working in this repository. `CLAUDE.md` imports this file; edit here, not there.

## Project Structure & Module Organization

MOTCO is a Python package using the `src/` layout. Core package code lives in `src/motco/`; the CLI entry point is `src/motco/cli.py`, the real-data pipeline is `src/motco/analysis.py`, and statistical routines are split under `src/motco/stats/` (`design.py`, `trajectory.py`, `permutation.py`, `interaction.py`, `pls.py`, `sparse_pls.py`, `snf.py`, `attribution.py`). The simulation framework is under `src/motco/simulations/`, with the declarative study engine in `src/motco/simulations/study/`. Validation and study drivers are in `scripts/`. Tests live in `tests/`, with fixtures and reference CSV/R data under `tests/data/`. Documentation is in `docs/` and is built with MkDocs using `mkdocs.yml`; dated findings reports are in `docs/reports/` and committed run aggregates in `results/`. Example usage is in `examples/motco_example.ipynb`, and committed study configs in `examples/trajectory_power_study/`. OpenSpec proposals and canonical specs are under `openspec/`. See [Architecture](#architecture) for module-level detail.

## Build, Test, and Development Commands

Use Python 3.11+ and `uv`.

```bash
# Install (lockfile-respecting, matches CI)
uv venv && source .venv/bin/activate
uv sync --extra test   # add --extra docs for MkDocs; or: uv pip install -e ".[test]"

# Lint
uv run ruff check src/ tests/

# Type check
uv run mypy src/motco/

# Run fast tests
MOTCO_TEST_PERMS=99 uv run pytest tests/ -m "not slow" --tb=short

# Run a single test file
uv run pytest tests/test_trajectory.py -v

# Run slow regression tests with parallelism (only on main in CI)
MOTCO_TEST_PERMS=10000 MOTCO_N_JOBS=-1 uv run pytest tests/ --tb=short

# Pre-commit gate — all three must pass before committing
uv run ruff check src/ tests/ && uv run mypy src/motco/ && MOTCO_TEST_PERMS=99 uv run pytest tests/ -m "not slow" --tb=short

# Docs preview
uv run mkdocs serve

# CLI entry point
motco --help
motco plsr --help
motco snf --help
motco simulate --help   # numpy generator (no R at runtime)
motco de --help
motco analyze --help    # real-data entry point (motco.analysis)
```

## Coding Style & Naming Conventions

Target Python 3.11. Keep line length at 120 characters, matching `pyproject.toml`. Ruff enforces `E`, `F`, `W`, and import-order (`I`) rules. Prefer explicit, descriptive function and variable names for statistical code; keep public APIs stable and documented with docstrings. Test files should follow `test_*.py` or `*_test.py`.

## Testing Guidelines

Tests use `pytest` with configuration in `pyproject.toml`. Slow tests are marked `slow`; use `MOTCO_TEST_PERMS=99` for fast permutation tests during development and the full regression command above before merging numerically sensitive changes. Add tests alongside behavior changes, especially for numerical fallbacks, CLI validation, and reference-data comparisons.

## Commit & Pull Request Guidelines

Follow the existing Conventional Commit style: `feat:`, `fix:`, `docs:`, `chore:`, and `refactor:`. Keep commits focused and imperative, for example `fix: handle singular model matrix fallback`. Pull requests should include a short problem statement, summary of changes, commands run, linked issues or OpenSpec changes when relevant, and screenshots only for documentation or rendered output changes. A change that bumps `__version__` adds its entry to `CHANGELOG.md` in the same change, listing package changes only (validation runs go in their reports). Pushing a `v<version>` tag on `main` publishes that version to PyPI and creates its GitHub release (`.github/workflows/publish.yml`). `scripts/release_notes.py` builds the release notes from every changelog entry since the previous tag, so untagged versions ship in the notes of the release that first includes them. The workflow stops before uploading when the tagged version has no entry, and `tests/test_release_notes.py` fails while `__version__` has none.

## Agent-Specific Instructions

When running shell commands as an agent, prefix commands with `rtk` if it is installed (`command -v rtk`); otherwise run them directly. Do not overwrite user changes; inspect the worktree before broad edits and keep changes scoped to the requested task. When a change alters architecture, defaults or conventions described below, update this file in the same change. Record a validation run's findings in its dated report under `docs/reports/` and its verdict in `docs/roadmap.md` (Next changes); here, add only the code it introduces and one row in [Validation drivers](#validation-drivers).

## Architecture

**The pipeline is features → latent (molecular) space → trajectory measurement, and this is load-bearing.** The integration step *constructs* the molecular latent space, and `delta` (size), `angle` (orientation) and `shape` are estimated *within* it; the latent space is the measurement substrate, not a visualization. **`pls` is the production measurement space**: the omic features are standardized, concatenated and projected onto the subspace maximizing covariance with the **stage** label, its rank chosen by double nested CV. `snf` is a supported integration path, but its use with the Euclidean statistics is deferred pending graph-native statistics (`docs/roadmap.md`). `concat` (standardized concatenation) is a baseline/diagnostic only. The viz down-projection (`viz.plot_trajectory_from_*`) is display-only; never conflate it with the latent space. What the production space can and cannot see is in `docs/measurement-visibility.md`.

### Trajectory statistics: `stats/design.py` → `stats/trajectory.py` → `stats/permutation.py`

- **`design.py`.** `get_model_matrix(X, group_col, level_col, full)` builds an intercept + dummy-coded design with optional group×level interactions (category order deterministic: sorted string representation). `build_ls_means(group_levels, level_levels, full)` builds LS-mean rows consistent with that coding, group-major, level-minor. `build_covariate_matrix` codes covariates (numeric as-is, factors drop-first `name[level]`); `build_conditioning_matrix` builds stage or group/stage/interaction indicators for latent adjustment. `center_matrix` is a column-centering helper.
- **`trajectory.py`.** `estimate_difference(Y, model_matrix, LS_means, contrast, orientation_estimator=)` fits betas by normal equations (Cholesky → direct solve → lstsq fallback) and returns symmetric `(deltas, angles, shapes)`: size is path length, orientation the angle between group directions, shape strict pairwise ordinary Procrustes over all orthogonal transforms (reflections aligned away at every ambient dimension). `estimate_betas`, `get_observed_vectors` and `pair_difference` expose the prediction step.
  - **Orientation estimator.** The primitives default to `"pc1"` (PC1 of each group's centred stage means); `"net_displacement"` uses the unit vector `stage_last − stage_first` (equal to PC1 at two stages, `NaN` on a zero displacement). Only `angle` depends on it. The simulation harness and `motco analyze` default to net displacement, so code calling the primitives directly must pass `orientation_estimator="net_displacement"` to measure what they measure.
  - **PC1's sign convention deviates deliberately from the reference supplement**: it is signed by `PC1 · (stage_last − stage_first)`, not by the supplement's raw first-stage row (`evo_649_sm_suppmat.r:64`), which would make the sign depend on the position relative to the origin. See `_estimate_orientation` and `tests/test_trajectory_orientation.py`.
- **`permutation.py`.** `RRPP(Y, model_full, model_reduced, LS_means, contrast, permutations, n_jobs, orientation_estimator=, residual_correction=)` permutes the reduced model's residuals and re-estimates per draw; serial by default, parallel via `multiprocessing.Pool` with the picklable `_RRPPWorker`. Opt-in `residual_correction` (`RESIDUAL_CORRECTIONS = ("df", "leverage")`) rescales the reduced residuals once before any draw — `df` by κ = √(n / (n − r)), `leverage` by 1/√(1 − h_ii) — leaving the permutation indices and fitted values unchanged; `residual_correction_scale` raises for an unknown value, n − r ≤ 0 or a leverage-1 row. `None` is byte-identical to the uncorrected path.
- **`interaction.py`** (imports nothing from `motco.simulations`; the caller maps features to coordinates). `interaction_split_test(Y, model_full, model_reduced, basis, *, permutations, seed, residual_correction, return_null)` tests the group × stage interaction in three parts — `total`, `span` (`Y·Q·Qᵀ`) and `complement` — each by a trace pseudo-F (the statistic) and interaction SS (a diagnostic) under Freedman–Lane permutation with `RRPP`'s serial draws and corrections, on each part's n × n reduced-residual Gram matrix (O(n²) per draw). `interaction_feature_scan(Y, model_full, model_reduced, *, permutations, seed, residual_correction, return_null, blocks=None)` tests each column's interaction F, with the global p-value from the maximum and Westfall–Young step-down max-T adjusted p-values on the same draws (a constant `df` multiplier is not applied: it cancels in every F); degenerate columns get no F and leave every maximum. With `blocks` (one label per column; `INTERACTION_SCAN_COMBINATIONS` = `joint` | `block_bonferroni`) the step-down runs within each block and the K tested blocks are combined by Bonferroni; one label reproduces the joint scan exactly, and without labels the outputs are byte-identical to the joint scan's. Tests: `tests/test_interaction_split.py`, `tests/test_interaction_scan.py`.

### Latent spaces and attribution: `stats/pls.py`, `stats/sparse_pls.py`, `stats/snf.py`, `stats/attribution.py`

- **`pls.py`.** `plsda_doubleCV` — the outer loop (CV2) picks the best model per repeat, the inner loop (CV1) selects the number of latent variables by AUROC; returns `{"table": DataFrame, "models": [PLSRegression, ...]}`, optional `n_jobs`. Keyword-only options, each byte-identical at its default (`tests/data/plsda_doublecv_identity.json`): `scale`; `nuisance` (a `NuisanceDesign`: each training set estimates its own covariate coefficients on `[1, conditioning, covariates]` via `fit_nuisance_coefficients` and residualizes its held-out rows via `residualize`); `strata` (fold labels instead of `y`); `min_components` (default 1; candidates `min_components … max_components − 1`, a `ValueError` before any fit otherwise — the floor of 2 is the trajectory measurement's rule, not the primitive's); `sparsity` (a `SparsityDesign`: every fit is a `SparsePLSDA`, the inner loop scores every (rank, keep fraction) pair ordered rank ascending then fraction descending, each repeat takes the modal rank and the fullest modal fraction, and the table gains `keep_fraction`; a `[1.0]` ladder reproduces the dense run). `fit_plsda_model(..., sparsity=, keep_fraction=)` fits the same estimator; `calculate_vips(model)` computes VIP scores.
- **`sparse_pls.py`.** `SparsePLSDA(n_components, keep, *, groups=None, scale=True, max_iter=1000, tol=1e-6)` subclasses `PLSRegression` and overrides only `fit`: at the full budget it calls `PLSRegression.fit` bit for bit; below it it mirrors sklearn's NIPALS (reusing sklearn's helpers) with the X weight soft-thresholded per group before normalization (keep the `keep` largest absolute entries, shrink them by the largest discarded one). It inherits `transform`/`predict`/`x_rotations_`, so every PLS consumer accepts it, and adds `keep_`, `support_` and `support_sizes(groups)`. `SparsityDesign(scope, keep_fractions=DEFAULT_KEEP_FRACTIONS, feature_groups=None)`: `SPARSITY_SCOPES` = `joint` | `block` (block needs groups), ladder 1.0/0.5/0.2/0.1/0.05, counts `max(1, round(f·p_g))`. Reference: `tests/data/splsda_reference_fixture.npz` from mixOmics 6.34.0 `splsda` (`tests/data/reference/splsda_fixture.R`, packed by `tests/splsda_fixture_capture.py`). Tests: `tests/test_sparse_pls.py`, `tests/test_plsda_sparsity.py`.
- **`snf.py`.** `get_affinity_matrix` → `SNF` → optional `get_spectral(n_components=10)`. Input datasets must be sample-aligned (same rows, same order).
- **`attribution.py`.** `analyze_orientation_attribution` explains a two-group, multi-stage orientation difference in one fixed pooled PLS space: the observed normalized feature contrast, its PLS-reconstructed counterpart and their residual, for adjacent transitions and for the signed principal orientations (with an eigengap degeneracy flag); bootstrap sign, rank and top-k stability within design strata; module and caller-supplied pathway summaries. With `covariates=` / `covariate_reference=` it attributes from covariate-adjusted cell means (the least-squares means of `X ~ cells + C` at the reference row), refitting the coefficients in each bootstrap resample and counting rank-deficient resamples as invalid; without covariates its outputs are pinned by `tests/test_attribution_identity.py` (`tests/data/attribution_no_covariate_identity.json`). Pooled VIP is context only, never an orientation driver.

- **`cli.py`.** Argparse CLI with five subcommands — `plsr`, `snf`, `simulate` (one semi-synthetic dataset from the numpy generator, no R), `de` (`--orientation-estimator {pc1,net_displacement}`, default `pc1`; the JSON gains `orientation_estimator` only when the flag is given) and `analyze` (over `motco.analysis`, exposing every option above plus `--min-components`, default 2). `plsr --min-components` defaults to 1, the primitive's unfloored rule. - **`viz.py`.** Two-layer matplotlib API: `plot_trajectories(observed_vectors, projector, ...)` draws directed 2D paths from pre-computed LS-mean vectors and a fitted projector; `plot_trajectory_from_data(Y, metadata, group_col, level_col, ...)` fits PCA on `Y` and returns `(fig, ax, pca)`. ### Simulations: `src/motco/simulations/` (numpy-native; no R at runtime)

- **Generator and fidelity.** `reference.py` loads the cached InterSIM reference (`data/intersim_reference.npz`), produced once by `export_reference.R` + `build_cache_from_export(...)`. `generator.py` reimplements InterSIM's model (`μ = base + δ·v` → `MVN(μ, Σ)`, methylation `rev.logit` after the M-value shift, cross-omic coupling through the incidence maps); `generate_omics(...)` samples per cell from explicit differential indicators, with optional per-cell mean shifts (`cell_shift_*`). `intersim.py` is the legacy bridge to R InterSIM, used by nothing at runtime. `fidelity.py` validates the generator against InterSIM by a per-omic statistic battery over a `delta × p.DMP` grid (`tests/data/intersim_fidelity_fixture.npz`, regenerated by `fidelity_intersim.R`); `fidelity_visual.py` renders the qualitative supplement (InterSIM raw matrices are regenerated, not committed). Protocol: `simulations/FIDELITY.md`. Tests: `tests/test_generator.py`, `tests/test_generator_fidelity.py`, `tests/test_fidelity_visual.py`.
- **`semisynthetic.py`.** `generate_semisynthetic_trajectory` → `SemiSyntheticTrajectoryDataset`. Group A is a random baseline trajectory; group B a deterministic transform selected by `trajectory_mode`, scaled by `group_effect_size` (0 = null for every mode). The default `construction` is **feature-set surgery** on the per-stage differential indicators: `magnitude` scales δ (`magnitude_kind='joint'`, the default, scales all three per-omic δ by `1 + e`; `'all'` is the methylation-only historical construction the pre-flip configs pin; `'extremes'` scales the endpoint stages' methylation indicators), `orientation` is one global per-omic feature permutation, `shape` permutes interior stages, `translation` is a constant location offset, `none` is identical. Truth records per-stage/group indicators, per-omic δ and the construction parameters.
  - **Pool-limited surgeries** (`orientation`, `translation`, `shape_kind='relocate'`) draw from a finite CpG pool: `surgery_censoring="error"` (default) fails rather than realize a partial surgery, `"clamp"` keeps the old behaviour for historical configs; `expected_surgery_headroom(params)` gives the analytic headroom, which `study/enumerate.py` checks at config time.
  - **`baseline_continuity`** (ρ ∈ [0, 1)): per-CpG differential status follows a stationary Markov chain across stages, keeping the per-stage Bernoulli(`p_dmp`) marginal; ρ = 0 is byte-identical to the independent baseline.
  - **`group_stage_sizes`** fixes every group × stage cell (rows `group_labels`, columns stages) and conflicts with non-default `n_samples` / `stage_sample_prop` / `group_ratio`.
  - **Stage-span construction** (`construction="stage_span"`, `span_layers`): B keeps A's indicators (no RNG drawn: the null dataset plus a plant), and `_stage_span_plant` edits B's exact null population stage means in null-pooled-standardized coordinates — `magnitude` scales about the centroid, `orientation` rotates by 90°·e in the plane of the net displacement and the next principal direction, `shape` moves an interior stage off its chord at fixed path length, `translation` offsets along the net displacement (`edit_stage_configuration`). `span_alignment` (φ in degrees) and `span_support` tilt the rotation plane toward a seeded direction the null stage program does not use; `span_scale="planted"` solves the edit as a fixed point so it is exact under the planted pooled SD. Tests: `tests/test_stage_span_construction.py`, `tests/test_span_alignment.py`, `tests/test_span_scale.py`.
- **`preprocessing.py`.** `fit_block_scalers` / `transform_blocks` / `concatenate_blocks(order=)`, `fit_omics_preprocessor` (`FittedOmicsPreprocessor`), `selected_layers` (block selection, canonical order) and `BLOCK_WEIGHTINGS` (`equal_variance` = 1/√p_b; `mfa` = √n/σ₁(Z_b)), fitted once on the pooled sample.
- **`evaluation.py`.** `evaluate_semisynthetic_trajectory` runs one dataset through integration → design → `estimate_difference` → optional RRPP and returns `SimulationEvaluationResult`; `integrate_semisynthetic_dataset` and `evaluate_...(latent=)` let evaluations differing only in measurement share one fit. `fit_pls_latent_space` is the production core shared with `motco analyze`. Every option below is hash-omitted while unset and byte-identical when absent:
  - `integration_params["layers"]` restricts preprocessing, integration, realized geometry and attribution to the named blocks; `["block_weighting"]` and `["sparsity"]` (`{"scope", "keep_fractions"}`) as in `motco analyze` (PLS fits with `scale=False` under weighting; sparsity only with `pls` and `pls_residual_pca`; a forced rank needs a one-element ladder); `["forced_components"]` skips CV. Tests: `tests/test_block_weighting.py`, `tests/test_sparse_latent_space.py`.
  - Integration methods: `pls` (production), `snf`, `concat` (baseline), and the diagnostic-only `pca` (at a required rank), `pls_within_group` (per-group stage PLS merged by pivoted QR, fitted once, never inside RRPP) and `pls_residual_pca` (the production fit plus stage-residual components orthogonal to its span; `pls_residual_pca_from_pls` builds it without refitting). Diagnostic methods reject attribution and `forced_components`. Tests: `tests/test_pls_residual_pca.py`.
  - `SimulationEvaluationParams.orientation_estimator` (default `"net_displacement"`; `"pc1"` normalizes to `None`, the hash-omitted spelling) drives the observed `angle`, every RRPP draw and every checkpoint.
  - `min_components` (default 2; `1` normalizes to `None`): CV candidates `min_components … max_components − 1`, `max_components` clamped to `[min_components + 1, min(n_features, n_samples)]`, a sample that cannot meet the floor is an error; a forced rank ignores the floor. Tests: `tests/test_rank_floor.py`.
  - `span_capture` hands the fitted `LinearLatentMap` (`diagnostics.py`; PLS via `from_pls`, also `pca`, `pls_residual_pca`, standardized `concat`) to `calculate_realized_geometry(..., latent_map=)`, adding the `population_latent` checkpoint and the energy shares of the population group difference and pooled stage means inside the fitted span. Tests: `tests/test_span_capture.py`.
  - `latent_coordinates="orthonormal"` measures on `X_in·qr(x_rotations_)` with the same fit, rank and draws (`LinearLatentMap.from_pls_orthonormal`, `pls_orthonormal_from_pls`); PLS only, rejected with attribution. Not adopted: production stays on scores. Tests: `tests/test_orthonormal_coordinates.py`.
  - A stage-span dataset whose `span_layers` differ from the measured blocks is refused before any fit (`_require_span_layers_measured`).
- **`grid.py`.** Replicate runs over a `SimulationGrid` of `SimulationCell`s (`generator_params` + `evaluation_params`): resumable JSONL persistence keyed by parameter signature, Type I / power grid enumeration, `summarize_rejection_rates` and `summarize_realized_surgery`. `_SIGNATURE_OMIT_WHEN_NONE` (`group_stage_sizes`, `orientation_estimator`, `min_components`, `construction`, `span_layers`, `span_capture`, `span_alignment`, `span_support`, `span_scale`, `latent_coordinates`) leaves a field out of cell ids, signatures and records while `None`, so a historical spelling hashes as if the field never existed. Null Type I cells clear the construction.
- **Other modules.** `attribution_diagnostics.py` (attribution on the harness's fitted estimator), `diagnostics.py` (realized-geometry checkpoints, `LinearLatentMap`, span capture), `pivotality.py` (the `angle`-null pivotality tables), `specificity.py` (dominant-specificity and geometry-specificity probes), `showcase.py` (illustrative per-mode figures, not the power study) and the one-off recovery probes (`*_recovery.py`, `pls_inverse.py`, `realized_geometry_study.py`).
- **`study/`** — the declarative, cluster-executable power study; its operational handbook is `simulations/study/README.md`. `config` (`StudyConfig`; the loader rejects unknown top-level keys), `enumerate`, `sharding`, `merge`, `summary`, `spectrum`, `report`, `targets`, `phase4` (the Phase 4 gate). Axes are namespaced `generator.<field>` / `evaluation.<field>`, plus the one nested form `evaluation.integration_params.<key>` (`null` = key absent). A `design_grid` is crossed (`axes`) or explicit (`points`, baseline listed, no duplicates); its non-baseline points enumerate phase `power_design` in the primary matched-seed family, invisible to the baseline readers. Constructions are sibling profiles in one seed family, never an axis. Advisory acceptance rules: `gate`, `type_i` (optionally column-scoped by `trajectory_mode` and `statistic`), `specificity` (`bound` `two_sided` | `upper`), `anchor_decision`, `column_decision`, `rank_decision`, `design_point`; an optional `report_contract` adds `driver_report.csv` / `report_contract.json`. Reports add `design_point_operating.csv`, `design_point_stage_signal.csv` and `span_capture.csv` only when their inputs exist, so every committed report regenerates byte-identically. Drivers: `scripts/run_study_shard.py`, `scripts/motco_study.py` (`merge`, `report`), `scripts/motco_study_array.sbatch`.

### Validation drivers

Each validation question has a driver under `scripts/` and a dated report. The drivers share conventions: subcommands `run` | `merge` | `decide` (some add `calibrate`, `fidelity`, `--profile`); an sbatch array beside each (a profile env var, and a dry-run variable that prints the command); a `settings.json` bound by hash, so a resume or merge under other settings exits naming the keys; complete units resumed; records hold seeds and statistics only. **Later drivers import earlier ones and their seed functions unchanged, and bind their parents' committed settings and tables by sha256, refusing a changed file by name** — editing a committed driver can break every child's reproduction. Decision rules carry a rule version and are amended only before any unit runs; multi-test rules use `judge_rates`, the count-plus-ceiling rule in `scripts/stage_span_paper_grade_decision.py`. Plasmode drivers read `sead_sexdiff`'s astrocyte export in place through a contract (`plasmode_check.ExportContractError`, file sha256 in the settings), analyse only within-stage-permuted labels and commit no donor id or label vector.

### Key conventions

- All model matrices must include an intercept column. `get_model_matrix` always prepends one.
- `contrast` is a `list[list[int]]`: each inner list enumerates the LS-mean row indices belonging to one group (group-major, level-minor indexing matches `build_ls_means`).
- `group_col` and `level_col` must always be passed explicitly — no defaults anywhere.
- **Opt-in features are byte-identical when absent.** Every option above changes nothing while unset; its identity fixture or test pins that, and new options must do the same. Harness parameters that are `None` are hash-omitted (`grid._SIGNATURE_OMIT_WHEN_NONE`), so adding one leaves committed cell ids, signatures and records unchanged.
- **Config pin policy.** The 19 study configs committed before the orientation flip are a closed historical set: they pin `orientation_estimator: "pc1"` and `min_components: 1`, checked by `tests/test_orientation_default_pins.py` and `tests/test_rank_floor_default_pins.py` against `tests/data/orientation_default_identity.json`, and the ten pre-joint ones pin `magnitude_kind: "all"`, checked by `tests/test_magnitude_default_pins.py` against `tests/data/historical_config_signatures.json`. Every config committed since names its estimator and rank floor explicitly and non-null and is pinned by `tests/data/post_floor_config_identity.json` (`tests/post_floor_fixture_capture.py`, `POST_FLOOR_CONFIGS`). Every file under `examples/trajectory_power_study/` must be in exactly one of the two fixtures; `tests/test_committed_config_identity.py` pins every committed config's cell ids, signatures and matched seeds. In a study config, `null` names the evaluator's default and `"pc1"` names PC1. Historical diagnostics and fixture captures that pin `"pc1"` also pin `min_components=1`.
- **Committed records stay frozen.** Phase 5 artefacts (`results/phase5-2026-09-10`, its report, exit review and template) must stay byte-identical (`tests/test_phase5_magnitude_profiles.py`); regenerating a committed `report/` from its merged records must reproduce it.
- `MOTCO_TEST_PERMS` controls permutation count in regression tests (default `10000`). `MOTCO_N_JOBS` controls RRPP parallelism (default `1`; use `-1` for all CPUs).
- Regression test reference values are in `tests/data/results_example1.csv` and `tests/data/results_example2.csv`. `tests/data/reference/` contains the R scripts used to generate reference data, not CSV outputs.
- The package is built with `hatchling`; version is sourced from `src/motco/__init__.py`.
