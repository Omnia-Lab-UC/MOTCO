# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
# Install (lockfile-respecting, matches CI)
uv venv && source .venv/bin/activate
uv sync --extra test   # or: uv pip install -e ".[test]"

# Lint
uv run ruff check src/ tests/

# Type check
uv run mypy src/motco/

# Run fast tests
MOTCO_TEST_PERMS=99 uv run pytest tests/ -m "not slow" --tb=short

# Run a single test file
uv run pytest tests/test_trajectory.py -v

# Run slow regression tests with parallelism (only on main in CI)
MOTCO_TEST_PERMS=10000 MOTCO_N_JOBS=-1 uv run pytest tests/ --tb=short

# Pre-commit gate — all three must pass before committing
uv run ruff check src/ tests/ && uv run mypy src/motco/ && MOTCO_TEST_PERMS=99 uv run pytest tests/ -m "not slow" --tb=short

# CLI entry point
motco --help
motco plsr --help
motco snf --help
motco simulate --help   # numpy generator (no R at runtime)
motco de --help
motco analyze --help    # real-data entry point (motco.analysis)
```

## Architecture

MOTCO is a Python package (`src/motco/`) with a CLI entry point (`motco`) and statistical modules under `src/motco/stats/`:

- **`stats/pls.py`** — PLS-DA with double cross-validation (`plsda_doubleCV`). The outer loop (CV2) picks the best model per repeat; the inner loop (CV1) selects the number of latent variables by AUROC. Returns a dict with `"table"` (DataFrame) and `"models"` (list of fitted `PLSRegression`). Optional parallelism via `n_jobs`. `calculate_vips(model)` computes VIP scores from a fitted model.

- **`stats/snf.py`** — Similarity Network Fusion. `get_affinity_matrix` → `SNF` → optional `get_spectral(n_components=10)`. Input datasets must be sample-aligned (same rows, same order).

- **`cli.py`** — Argparse CLI with five subcommands: `plsr`, `snf`, `simulate` (semi-synthetic multi-omic dataset via the numpy generator, no R), `de` (`--orientation-estimator {pc1,net_displacement}`, default `pc1`; the JSON gains an `orientation_estimator` key only when the flag is given, so default output is byte-identical), `analyze` (over `motco.analysis`). Each wraps the corresponding module and converts `ValueError` to clean `SystemExit` messages.

- **`analysis.py`** — The **real-data entry point** (`analyze_trajectories(TrajectoryDataset, TrajectoryAnalysisParams)` → `TrajectoryAnalysisResult`; `write_analysis_outputs`; CLI `motco analyze`). Inputs: named `OmicsBlock`s (any names/count, declared unit transform `identity` | `beta_to_mvalue`, concatenated in declared order as `block__feature`), metadata with caller-named sample/group/stage columns, exactly two groups, and an **explicit `stage_order`** (load-bearing for net displacement; never sorted) — honoured by recoding group/stage to ordinal strings before `build_simulation_trajectory_design` and mapping levels back. It calls the **same cores** as the harness (`preprocessing.fit_block_scalers`/`transform_blocks`/`concatenate_blocks(order=)`, `evaluation.fit_pls_latent_space`, the record helpers), so `tests/test_analysis.py::test_matches_harness_*` requires identical latent matrices, statistics, p-values, rank, null summary and spectrum. Defaults: `orientation_estimator="net_displacement"`, harness CV knobs, `forced_components` for dimensionality sensitivity. The record carries statistics, p-values, `null_summary`, `config_spectrum`, latent metadata (selected rank, component selection), design (ordered levels, cell sizes), block units, params and software versions — no `truth_metadata`/`realized_geometry`. Attribution (optional) reuses the fitted estimator via `attribution_diagnostics.run_attribution_diagnostics` with an unavailable `TruthDrivers`. The artifact is `result.json`, `latent_scores.csv`, `pls_loadings.csv`, `stage_means.csv` (+ `attribution/`); the estimator is never pickled. No covariates, normalization, filtering or imputation (documented limitation).

- **`viz.py`** — Visualization. Two-layer matplotlib API for trajectory geometry:
  - `plot_trajectories(observed_vectors, projector, ...)` — core function; takes pre-computed LS-mean vectors (output of `get_observed_vectors`) and a fitted projector, draws directed 2D paths with per-segment direction arrows.
  - `plot_trajectory_from_data(Y, metadata, group_col, level_col, ...)` — convenience wrapper; fits PCA on `Y` and returns `(fig, ax, pca)` so the projector can be reused.

- **`simulations/`** — Semi-synthetic simulation framework (numpy-native; no R at runtime):
  - `reference.py` — Loads the cached InterSIM reference data (`data/intersim_reference.npz`: per-omic means/covariances, cross-omic incidence maps, correlation vectors) with `load_reference()`. The cache is produced once by `export_reference.R` (run in R) + `build_cache_from_export(...)`; runtime never touches R.
  - `generator.py` — numpy reimplementation of InterSIM's generative model (`μ = base + δ·v` → `MVN(μ, Σ)`, methylation `rev.logit` after the M-value shift, cross-omic coupling via the incidence maps). `generate_omics(...)` samples per-cell from explicit differential indicators and returns matrices + indicator truth. Realism is validated against an InterSIM fixture in `tests/test_generator.py`.
  - `intersim.py` — Legacy bridge to the R InterSIM package, retained **only** for the one-time reference-data export; not used in runtime generation.
  - `fidelity.py` — Paper-grade fidelity validation of the numpy generator against InterSIM: a per-omic statistic battery (`compute_statistics`), a `delta × p.DMP` grid (`default_grid`), a numpy cell runner over the real generator (`run_numpy_cell`), and the replicate-distribution criterion (`compare_cell`/`validate_grid` — numpy's replicate mean must fall in InterSIM's `[q2.5, q97.5]` interval). The InterSIM side is committed R-free as `tests/data/intersim_fidelity_fixture.npz`; `fidelity_intersim.R` regenerates it and `build_fidelity_fixture_from_export` packs it. Tests in `tests/test_generator_fidelity.py`; supplement via `scripts/fidelity_supplement.py`. See `simulations/FIDELITY.md` for the full protocol and reproduction steps.
  - `fidelity_visual.py` — Qualitative side-by-side InterSIM-vs-numpy figures (density, per-modality clustermap heatmaps with sample/feature dendrograms + cluster colour bar, per-modality PCA at 4 clusters, per-feature moment-agreement scatter, cross-omic coupling correlation block). Unlike the quantitative fixture, the InterSIM **raw matrices are not committed** (large; only needed to render the supplement) — regenerate them with InterSIM via `flake.nix` using `fidelity_visual_intersim.R` + `build_visual_fixture_from_export` (writes under gitignored `build/`); the numpy side is generated live. Entry point `run_fidelity_visual`; tests (R-free, synthetic stand-in fixture) in `tests/test_fidelity_visual.py`; CLI via `scripts/fidelity_visual.py`. See `simulations/FIDELITY.md`.
  - `semisynthetic.py` — Generates `SemiSyntheticTrajectoryDataset` from the numpy generator. Trajectory modes are **feature-set surgery** on per-stage differential indicators: group A is a random baseline trajectory; group B is a deterministic transform — `magnitude` scales δ (size; `magnitude_kind='joint'` — the default, also for `motco simulate` — scales all three per-omic δ by the same `1 + e`, which is size-pure in the joint standardized space and is the construction the Phase 5 magnitude re-measurement validated; `'all'` is the methylation-only historical construction (global methylation δ at every stage) that the committed pre-flip study configs and diagnostics pin explicitly; `'extremes'` scales only the endpoint stages' methylation indicators; `'extremes'` and `shape_kind='magnitude'` stay methylation-only), `orientation` is one global per-omic feature permutation (rotation), `shape` permutes interior stages only (bend), `translation` is a constant observed-space location offset, `none` is identical. `group_effect_size` is the unified knob (0 = null for every mode). Truth records per-stage/group indicators, per-omic δ, and the `magnitude_kind`. **Pool-limited surgeries** (`orientation`, `translation`, `shape` with `shape_kind='relocate'`) draw from a finite CpG pool, so a large effect can request more sites than exist: `surgery_censoring` is the policy — `"error"` (default) fails loudly rather than realize a partial surgery, `"clamp"` opts into the old silent-clamping behavior for historical configs and the showcase. Truth records nominal size, realized size, and a `censored` flag per surgery. `expected_surgery_headroom(params)` returns the analytic pool headroom (3σ guard band) and the saturating effect; `study/enumerate.py` uses it to reject over-headroom cells at config time. **Baseline continuity** (`baseline_continuity`, ρ ∈ [0, 1)) is the declared axis for group A's baseline geometry: per-CpG differential status follows a stationary first-order Markov chain across stages, preserving the per-stage Bernoulli(`p_dmp`) marginal at every ρ (so per-stage counts, δ semantics, and the cross-omic coupling are unchanged) while cross-stage correlation is ρ^|t−s|, making stage means *trend* instead of forming a near-isotropic simplex. ρ = 0 is the independent baseline, byte-identical to the pre-axis generator; ρ enters truth and the headroom's stage-active union `1 − (1−p_dmp)·(1 − p_dmp(1−ρ))^(n_stages−1)`, so higher ρ enlarges the pool-limited surgery headroom. **Explicit group × stage sizes** (`group_stage_sizes`, rows = `group_labels`, columns = stages) fix every cell exactly and conflict with non-default `n_samples`/`stage_sample_prop`/`group_ratio`; truth records them as `group_stage_sizes` only when set, and hash payloads (`grid._SIGNATURE_OMIT_WHEN_NONE`) omit the field while it is `None`, so absent-table cell ids, signatures and datasets are byte-identical to before the field existed.
  - `evaluation.py` — Runs one dataset through the full MOTCO pipeline (integration → design → `estimate_difference` → optional RRPP). Returns `SimulationEvaluationResult`. **Latent-space architecture (load-bearing):** the pipeline is **features → latent (molecular) space → trajectory measurement** — the *integration* step **constructs the molecular latent space**, and trajectory geometry (`delta`/`angle`/`shape`) is estimated **within** it; that latent space *is the measurement substrate*, not a visualization. **`pls` is the production measurement space** (transform of the omic features into the subspace maximizing covariance with the **stage** label; latent dimensionality chosen by double nested CV for a stable, non-overfitted space). `snf` (graph-spectral embedding) remains a supported integration path, but its use with the Euclidean trajectory statistics is deferred pending graph-native statistics — see `docs/roadmap.md` for the authoritative status. `concat` is a **baseline/diagnostic only** (standardized feature concatenation — *not* a constructed latent space). The viz down-projection (`viz.plot_trajectory_from_*`) is **display-only and distinct from measurement** — never conflate it with the latent space. **Block selection:** `integration_params["layers"]` (resolved by `preprocessing.selected_layers`; canonical order, non-empty, known, duplicate-free) restricts preprocessing, every integration method, realized geometry and attribution to the named omic blocks; the preprocessor records its fitted layers and refuses a mismatched set. Absent = all three blocks, byte-identical output and no `layers` metadata entry. **Diagnostic integration methods** (probe-only, `integration_role="diagnostic"`, never production): `pca` (label-free SVD scores of the `concat` matrix at a required `integration_params["n_components"]`) and `pls_within_group` (per-group `scale=False` stage PLS-DA, default `n_stages − 1` components per group, stacked `x_rotations_` orthonormalized by pivoted QR into one basis, pooled-centered projection; fitted once, never inside RRPP). Both reject attribution and `forced_components`, and each records its own latent checkpoint (`pca_latent`, `pls_within_group_latent`; `pls` keeps `pls_latent`, `snf`/`concat` record none). **Orientation estimator:** `SimulationEvaluationParams.orientation_estimator` (default `"net_displacement"`, adopted by the 2026-10-14 power comparison; `"pc1"` normalized to `None`, the hash-omitted spelling of PC1) drives the observed `angle`, every RRPP draw and every checkpoint `angle`. It is in `grid._SIGNATURE_OMIT_WHEN_NONE`, so PC1 cell ids, signatures and records equal those from before the field existed; the default is hashed and written to `runtime_metadata`. Every committed study config and every historical diagnostic (`realized_geometry_study`, `specificity`, `scripts/latent_rank_probe.py`, the byte-identity fixture captures) pins `"pc1"` (`tests/test_orientation_default_pins.py` against `tests/data/orientation_default_identity.json`); in a study config `null` names the evaluator's default and `"pc1"` names PC1. `evaluate_semisynthetic_trajectory(..., latent=)` accepts a prebuilt integration so evaluations differing only in measurement share one fit. Driver: `scripts/orientation_measurement_probe.py` (5 spaces × 2 estimators on matched seeds at the Phase 6 and Phase 5 designs, resumable/sharded via `scripts/orientation_probe_array.sbatch`, advisory `advancement_decision.json`); motivating evidence: `scripts/orientation_checkpoint_evidence.py`; default byte identity pinned by `tests/test_orientation_probe_byte_identity.py`.
  - `grid.py` — Orchestrates replicate runs across a `SimulationGrid` of `SimulationCell` parameter combinations (`generator_params` + `evaluation_params`). Supports resumable JSONL persistence, Type I / power grid enumeration, rejection-rate summarization, and `summarize_realized_surgery` (per-cell nominal/realized surgery size and censored fraction, read from replicate truth).
  - `specificity.py` — Dominant-specificity instrumentation: per mode, measures the group-vs-stage projection and per-statistic RRPP rejection rates to confirm each mode predominantly moves its target statistic (`magnitude`→`delta`, `orientation`→`angle`, `shape`→`shape`). Also exposes the geometry-specificity probes: `characterize_two_stage` (shape-free `n_stages=2` isolation) and `evaluate_shape_null` (observed Procrustes distance vs RRPP-null quantiles under raw/concat-standardize/SNF integration). Driver: `scripts/geometry_specificity_probe.py`.
  - `showcase.py` — Illustrative demo (not the power study): generates one dataset per `trajectory_mode` from a shared baseline (same seed) and renders a per-scenario 2-component PLS-DA trajectory figure. `run_trajectory_showcase()` is the entry point; driven by `scripts/trajectory_showcase.py`.
  - `study/` — Declarative, cluster-executable trajectory power study (the engine behind the Type I / power validation of the `delta`/`angle`/`shape` tests). Submodules: `config` (`StudyConfig` + acceptance targets), `enumerate`, `sharding`, `merge`, `summary`, `spectrum`, `report`, `targets`. `spectrum` builds the recorded-covariate tables: eigengap-stratified power and — when a study sweeps `generator.baseline_continuity` — `continuity_resolved_orientation.csv` (orientation rejection rates, eigengap distribution, and `angle` null-width dispersion per continuity value). A config may also declare a **crossed `design_grid`** (every combination of the named generator/evaluation axes, baseline column required): each non-baseline design point enumerates its own anchored power grid as phase `power_design` in the primary matched-seed family, invisible to the baseline readers (curves, gate, targets); reporting adds `design_point_operating.csv` (rate, eigengap, `angle` null width, selected rank per point), a power figure, and — when `acceptance.design_point` declares the rule — an advisory `design_point_decision.json` (first confirmed column in preference order, else `revise_claim`). The committed Phase 5 design-point pilot is `examples/trajectory_power_study/phase5_design_point_pilot.json`. Axes (OFAT and design-grid) may also name the one **nested evaluation form** `evaluation.integration_params.<key>` (`null` = key absent, so the baseline column is byte-identical to a config without the axis); design columns that differ only in an evaluation-namespace axis share generator parameters and matched seeds — same data, different measurement. The retained-rank axis `evaluation.integration_params.forced_components` (`null` = CV) drives the **latent-rank ladder**: `design_point_operating.csv` gains `component_selection` (`cv`/`forced`), the report writes `rank_ladder.png`, and `acceptance.rank_decision` (advisory; target orientation/`angle`, protected magnitude/`delta` and shape/`shape`, anchor Type I bound, pooled-SE gain/loss multipliers) yields `rank_decision.json` — `keep_cv` or `adopt_fixed_rank` with the smallest qualifying rank. The production forced-rank guard admits forced records only at a declared rank design point. The committed ladder is `examples/trajectory_power_study/phase5_latent_rank_ladder.json`; its 2026-09-08 run returned `keep_cv` (`docs/reports/latent-rank-ladder-2026-09-08.md`), so Phase 5 keeps the stage-supervised double-CV rank rule. A design grid may instead be declared in the **explicit form** `design_grid.points` (a list of `{axis: value}` points, every point naming the same axes, the baseline point listed, no duplicates after normalization — `null` ≡ the evaluator's default (`"net_displacement"`) and `"pc1"` is its own value for `evaluation.orientation_estimator`; mutually exclusive with `axes`, from which `axes` is derived) for non-rectangular measurement columns; a point list equal to a full cross enumerates identically to the crossed form. `evaluation.orientation_estimator` and `evaluation.integration_method` are contracted design axes (`concat`/`pca` columns report no component selection). `acceptance.anchor_decision` (`alpha`, `se_multiplier`, `statistics`; advisory) makes the report write `anchor_decision.json`/`.csv`: per design point and statistic, anchor rate vs α + k·√(α(1 − α)/R) with R the available replicates (`holds`/`exceeds`/`unavailable`; point verdict `size_holds`/`excess`/`unavailable`), other negative controls descriptive. The committed **net-displacement Type I profiles** `net_displacement_type_i_phase6.json` and `net_displacement_type_i_phase5.json` (null-only: anchor + translation at e = 1.0, five explicit columns, 500 × 999, 12 cells each, parent seed families — note `evaluation.seed` is also the RRPP seed, so their baseline column reproduces the parent records exactly) feed `scripts/net_displacement_follow_up.py`, which writes `follow_up_decision.json` (`paper_grade_power_comparison` | `diagnose_anchor_excess`). Their 2026-10-13 run held size at every column at both designs (lead arm anchor `angle` 0.050, bound 0.0695) and selected `paper_grade_power_comparison` (`docs/reports/net-displacement-type-i-2026-10-13.md`). `acceptance.column_decision` (advisory; `candidate` design point, `target` pair with `criterion` `gain`|`no_loss` at the top effect, mandatory `controls` held to the one-sided anchor bound, `protected` pairs, `type_i_bound`, pooled-SE multipliers) makes the report write `column_decision.json`/`.csv` (`candidate_qualifies`/`candidate_fails`/`unavailable`; the baseline is measured, not judged). The committed **net-displacement power profiles** `net_displacement_power_phase6.json` (`gain`) and `net_displacement_power_phase5.json` (`no_loss`) run `pls_cv × pc1` vs `pls_cv × net_displacement` over four modes at e = 0.25–1.0, 500 × 999, 36 cells / 18,000 units each, in the parent seed families; `scripts/net_displacement_power_follow_up.py` writes `comparison_decision.json` (`adopt_net_displacement` | `keep_pc1`) and `scripts/net_displacement_power_checks.py` verifies identical `delta`/`shape` p-values between columns and parent reproduction (paired within one `magnitude_kind`). Their 2026-10-14 run selected `adopt_net_displacement` (orientation/`angle` 0.300 → 0.648 at Phase 6, 0.840 → 0.924 at Phase 5; shape → `angle` leak removed; `docs/reports/net-displacement-power-2026-10-14.md`); the harness default flipped to net displacement in `default-net-displacement-orientation` (2026-10-15), with every committed config pinned to `"pc1"`. A config may also declare a top-level **`report_contract`** (`driver_component` ∈ {observed, pls_captured, residual}; `cross_replicate_driver_agreement` fixed to `descriptive`; `n_jobs_override` `forbid`|`warn`): when present, `report` additionally writes `report/driver_report.csv` (declared component only, within-replicate bootstrap stability, no cross-replicate columns) and `report/report_contract.json` (resolved contract, uniform records `n_jobs`, the shared zero-effect anchor's `cell_id`/`resolves_modes`/`counted_as: 1`), the attribution figure plots within-replicate stability only, and under `forbid` `scripts/run_study_shard.py` exits 2 on a differing `--n-jobs`; without the block every output is byte-identical to before. The trajectory pipeline (group differences) is split across three modules — `design` → `trajectory` → `permutation`:

- **`stats/design.py`** — Design construction.
  1. `get_model_matrix(X, group_col, level_col, full)` — builds an intercept + dummy-coded design matrix with optional group×level interactions. Category order is deterministic (sorted string representation).
  2. `build_ls_means(group_levels, level_levels, full)` — generates the LS-mean row vectors consistent with the coding from `get_model_matrix`. Row order is group-major, level-minor.
  - `center_matrix(...)` — column-centering helper used by the estimators.

- **`stats/trajectory.py`** — Estimation + geometric metrics.
  - `estimate_difference(Y, model_matrix, LS_means, contrast)` — fits betas via normal equations (Cholesky → direct solve → lstsq fallback), then computes per-group trajectory size (`_estimate_size`), orientation (`_estimate_orientation` via eigendecomposition), and shape (`_estimate_shape` via strict pairwise ordinary Procrustes alignment over all orthogonal transforms — reflections aligned away at every ambient dimension). Returns symmetric matrices `(deltas, angles, shapes)`. `estimate_betas`, `get_observed_vectors`, and `pair_difference` expose the beta/LS-mean prediction step directly.
  - **Net-displacement estimator (opt-in at the primitives, harness default).** `estimate_difference(..., orientation_estimator="net_displacement")` (also on `RRPP` / `_RRPPWorker` and `diagnostics.geometry_from_means`) measures each group's orientation as the unit vector `stage_last − stage_first`; it equals PC1 at two stages, stays defined on near-isotropic configurations, and gives `NaN` (reported unavailable) on a zero displacement. Only `angle` depends on it; the primitives' default `"pc1"` is byte-identical. The simulation harness defaults to net displacement, so real-data code calling the primitives directly must pass `orientation_estimator="net_displacement"` to measure what the harness measures.
  - **Orientation sign convention deviates deliberately from the reference supplement.** PC1 is signed by net displacement `PC1 · (stage_last − stage_first)`, not by the supplement's raw first-stage row (`evo_649_sm_suppmat.r:64`), which would make the sign depend on the trajectory's position relative to the coordinate origin. See the `_estimate_orientation` docstring and `tests/test_trajectory_orientation.py` for the invariance contract.

- **`stats/permutation.py`** — `RRPP(Y, model_full, model_reduced, LS_means, contrast, permutations, n_jobs)` — permutes residuals of the reduced model and calls `estimate_difference` for each permutation. Serial by default; parallel via `multiprocessing.Pool` using `_RRPPWorker` (a picklable callable).

### Key conventions

- All model matrices must include an intercept column. `get_model_matrix` always prepends one.
- `contrast` is a `list[list[int]]`: each inner list enumerates the LS-mean row indices belonging to one group (group-major, level-minor indexing matches `build_ls_means`).
- `group_col` and `level_col` must always be passed explicitly — no defaults anywhere.
- `MOTCO_TEST_PERMS` controls permutation count in regression tests (default `10000`). `MOTCO_N_JOBS` controls RRPP parallelism (default `1`; use `-1` for all CPUs).
- Regression test reference values are in `tests/data/results_example1.csv` and `tests/data/results_example2.csv`. `tests/data/reference/` contains the R script used to generate them, not CSV outputs.
- The package is built with `hatchling`; version is sourced from `src/motco/__init__.py`.
